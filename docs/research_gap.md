# Research Gap — What We Enhance and Why

## Baseline: existing IEEE ML-based IoT-IDS approaches

Published ML-IDS systems for IoT (including the CICIoT2023 reference models and
typical IEEE conference implementations) share five structural limitations:

1. **Centralized** — all raw traffic is shipped to one server for training and
   inference. Bandwidth-heavy, a single point of failure, and unusable where
   data cannot legally leave the premises (hospitals, factories).
2. **Too heavy for the edge** — server-class float32 networks (our measured
   baseline reproduction: see `docs/results.md` for its size and latency);
   cannot run on gateway/router-class hardware.
3. **Non-private** — raw flows (device behaviour, usage patterns, medical
   telemetry) are exposed in transit and at rest on the server.
4. **Black-box** — a label with no reasoning. SOC operators can't triage or
   trust what they can't inspect; regulators increasingly require explanations.
5. **No real-time operational view** — results live in notebooks/CSVs, not in a
   monitoring surface an operator could actually use.

## EdgeShield AI — the enhancement, point by point

| Gap | Fix | Where it's real in this repo |
|---|---|---|
| Centralized | Edge inference on-gateway | int8 ONNX served by `ml-inference-service`, latency measured per request |
| Heavy | Small MLP + int8 post-training quantization | `ml-engine/quantize.py`, sizes/latency in `benchmarks/results.json` |
| Non-private | Federated training (FedAvg, 5 non-IID clients) — weights only leave devices | `federated-learning/run_federated.py`, real per-round curve in `history.json` |
| Black-box | SHAP attributions per class + per instance | `ml-inference-service/explain/`, live `/explain` endpoint |
| No visibility | Real-time SOC dashboard fed only by live inference events | `backend/` + `frontend/` |

## Evidence policy

Claims above are backed by the measured comparison in `docs/results.md`
(generated by `benchmarks/compare_baseline.py` on the demo machine — trained
baseline vs trained EdgeShield on the same held-out test set, same hardware).
The baseline is our faithful reproduction of the centralized approach (large
float32 MLP, pooled data), so the comparison is like-for-like: same data, same
split, same machine.
